**HƯỚNG DẪN VIẾT BÁO CÁO BÀI TẬP LỚN**

**Môn học:** Phát triển phần mềm hướng dịch vụ

**Định hướng đặt tên đề tài:**

Tên đề tài cần phản ánh đầy đủ **hai thành phần chính của hệ thống**:

- **Dịch vụ phía máy chủ (Backend Service/API):** cung cấp các chức năng nghiệp vụ và dữ liệu thông qua API.
- **Ứng dụng khách (Client Application):** tiêu thụ và sử dụng API để cung cấp chức năng cho người dùng.

Đề tài nên thể hiện rõ việc **thiết kế, xây dựng, triển khai và tích hợp các dịch vụ phần mềm**, thay vì chỉ mô tả việc xây dựng một ứng dụng web hoặc ứng dụng quản lý độc lập.

**Có thể tham khảo các cách đặt tên sau:**

**1\. Thiết kế và phát triển hệ thống ... theo kiến trúc hướng dịch vụ**

- Ví dụ: **Thiết kế và phát triển hệ thống quản lý cửa hàng theo kiến trúc hướng dịch vụ.**

Phù hợp khi bài tập lớn trình bày tổng thể kiến trúc hệ thống, bao gồm **API, các dịch vụ nghiệp vụ và ứng dụng client**.

**2\. Xây dựng dịch vụ API và ứng dụng client cho hệ thống ...**

- Ví dụ: **Xây dựng dịch vụ API và ứng dụng client cho hệ thống đặt vé xe trực tuyến.**

Tên đề tài trực tiếp thể hiện hai thành phần: **API Backend** và **Client tiêu thụ API**.

**3\. Phát triển hệ thống ... theo mô hình Client-Server dựa trên API**

- Ví dụ: **Phát triển hệ thống thương mại điện tử theo mô hình Client-Server dựa trên RESTful API.**

Phù hợp với các đề tài triển khai theo kiến trúc **Client-Server**, trong đó client và backend được tách thành các thành phần độc lập và giao tiếp thông qua API.

**4\. Thiết kế và triển khai hệ thống dịch vụ web cho ...**

- Ví dụ: **Thiết kế và triển khai hệ thống dịch vụ web cho bài toán quản lý phòng khám, tích hợp ứng dụng client.**

Phù hợp khi muốn nhấn mạnh quá trình **thiết kế, triển khai Web Service/API và tích hợp với phía client**.

**5\. Xây dựng và tích hợp dịch vụ API với ứng dụng client cho ...**

- Ví dụ: **Xây dựng và tích hợp dịch vụ API với ứng dụng client cho hệ thống quản lý thư viện.**

Phù hợp khi trọng tâm của đề tài là **xây dựng API, kiểm thử API và tích hợp API vào ứng dụng phía người dùng**.

**Khuyến nghị:**

Nên ưu tiên các cách đặt tên sử dụng các thuật ngữ như **API, Service, Client, Client-Server, RESTful API, kiến trúc hướng dịch vụ, tích hợp dịch vụ**. Điều này giúp tên đề tài phản ánh đúng phạm vi môn học và làm rõ rằng sản phẩm gồm **backend cung cấp dịch vụ** và **client tiêu thụ dịch vụ**.

**Không nên đặt tên quá chung chung** như: _Xây dựng website quản lý thư viện._

Vì tên này chưa thể hiện được đặc trưng của kiến trúc hướng dịch vụ.

Nên đặt theo hướng:

**Xây dựng RESTful API và ứng dụng client cho hệ thống quản lý thư viện.**

Hoặc:

**Thiết kế và phát triển hệ thống quản lý thư viện theo kiến trúc Client-Server dựa trên RESTful API.**

**KHUNG CÂU HỎI ĐỊNH HƯỚNG XÂY DỰNG BÁO CÁO**

Mỗi chương của báo cáo cần trả lời được các câu hỏi tương ứng. Báo cáo không chỉ trình bày **nhóm đã làm gì**, mà cần làm rõ **vấn đề gì cần giải quyết, giải quyết như thế nào, hệ thống được thiết kế ra sao, đã triển khai thế nào và kết quả có đáp ứng yêu cầu hay không**.

**Phân biệt với Chương 1**

**Chương 1 viết:**

Spring Boot là framework hỗ trợ phát triển ứng dụng Java, cung cấp cơ chế tự động cấu hình và hỗ trợ xây dựng ứng dụng web, RESTful API. Spring Boot được lựa chọn do khả năng xây dựng backend nhanh và tích hợp tốt với các công nghệ Java.

**Chương 3 viết:**

Hệ thống backend được xây dựng bằng Java 21 và Spring Boot 3.x. Dự án được quản lý bằng Maven và triển khai trên IntelliJ IDEA. Spring Data JPA được sử dụng để truy cập cơ sở dữ liệu MySQL 8.x.

**Không nên:** Lặp lại lịch sử, định nghĩa hoặc đặc điểm chung của Spring Boot trong Chương 3.

## 3.2. CÀI ĐẶT BACKEND SERVICE/API

**Mục đích:** Trình bày cách **hiện thực các thành phần backend đã được thiết kế ở Chương 2**.

Chương này không thiết kế lại API mà cần chứng minh các phân tích thiết kế đã thực hiện trong Chương 2 rằng: **Các thiết kế về kiến trúc, dữ liệu và API đã được chuyển thành mã nguồn và hệ thống chạy thực tế.**

**Cần trả lời**

- Backend được tổ chức thành các package và module như thế nào?
- Kiến trúc được thiết kế ở Chương 2 được hiện thực ra sao?
- Mỗi lớp thành phần chính đảm nhận trách nhiệm gì trong mã nguồn?
- Logic nghiệp vụ được triển khai ở đâu?
- Các API đã thiết kế được hiện thực bằng Controller như thế nào?
- Backend xử lý request, truy cập dữ liệu và trả response theo luồng nào?
- Những chức năng hoặc API quan trọng nào cần minh họa bằng mã nguồn?

### 3.2.1. Cấu trúc dự án Backend

Trình bày **cấu trúc thực tế của mã nguồn**, ví dụ:

src/main/java/com/example/application

|

|-- controller

|-- service

|-- repository

|-- entity

|-- dto

|-- config

|-- exception

|-- Application.java

Sau đó mô tả:

- controller: tiếp nhận HTTP request và trả HTTP response.
- service: triển khai xử lý nghiệp vụ.
- repository: thực hiện truy cập dữ liệu.
- entity: ánh xạ dữ liệu với cơ sở dữ liệu.
- dto: trao đổi dữ liệu giữa API và client.
- exception: xử lý các ngoại lệ phát sinh.

**Phân biệt với Chương 2**

**Chương 2:** Thiết kế backend theo kiến trúc phân tầng gồm Controller, Service và Repository, cũng có thể có sơ đồ các tầng kiến trúc

**Chương 3:**

Trình bày project thực tế đã tổ chức thành những package nào, class nào đảm nhận vai trò Controller, Service, Repository và cách chúng được liên kết.

Tức là:

**Chương 2: thiết kế kiến trúc.**

**Chương 3: hiện thực kiến trúc đó trong mã nguồn.**

### 3.2.2. Hiện thực mô hình dữ liệu và truy cập cơ sở dữ liệu

Cần trình bày:

- Entity được xây dựng như thế nào?
- Quan hệ giữa các Entity được hiện thực như thế nào?
- Repository được sử dụng để truy vấn dữ liệu ra sao?
- Cấu hình kết nối cơ sở dữ liệu như thế nào?

Chỉ nên đưa các Entity hoặc Repository tiêu biểu.

Không nên sao chép toàn bộ mã nguồn của tất cả các lớp vào báo cáo.

### 3.2.3. Hiện thực các API chính

Phần này cần phân biệt rõ với **thiết kế API ở Chương 2**.

**Chương 2 trả lời:**

API được thiết kế như thế nào?

Ví dụ:

| Method | Endpoint      | Request  | Response           |
| ------ | ------------- | -------- | ------------------ |
| GET    | /api/products | Không có | Danh sách sản phẩm |

**Chương 3 trả lời:**

API đó được lập trình và hoạt động như thế nào trong backend?

Có thể minh họa bằng mã nguồn thực tế.

Sau đó mô tả luồng, ví dụ:

GET /api/products ⇨ ProductController ⇨ ProductService ⇨ ProductRepository ⇨ MySQL Database ⇨ JSON Response

Nên chọn **một số API hoặc chức năng nghiệp vụ tiêu biểu**, không cần trình bày toàn bộ endpoint đã liệt kê.

### 3.2.4. Hiện thực xử lý nghiệp vụ

Cần trả lời:

- Logic nghiệp vụ được đặt tại lớp nào?

- Các API có thực hiện kiểm tra và xử lý ngoại lệ không?

Mục này giúp chứng minh backend không chỉ là tập hợp các API CRUD.

## 3.3. CÀI ĐẶT CLIENT APPLICATION

**Mục đích:** Trình bày cách **ứng dụng client đã được hiện thực và tích hợp với Backend API**.

Có thể đưa một đoạn mã tiêu biểu, nhưng không nên biến phần này thành hướng dẫn lập trình.

- **Chương 3 - Cài đặt và triển khai hệ thống:** Trình bày cách các thiết kế ở Chương 2 được hiện thực thành mã nguồn, cấu trúc dự án và hệ thống hoạt động thực tế.

Cách phân tách này (**lý thuyết → thiết kế → hiện thực → kiểm chứng**) nhằm tránh tình trạng **Chương 1 giới thiệu công nghệ xong sang Chương 3 lại giới thiệu lại Spring Boot, React, MySQL một lần nữa**.
